# Godot 场景与资源规范

## 1. 场景

场景用于组合节点、注入依赖和承载可复用结构。节点树层级应稳定、可读；脚本不得依赖无文档的深层相对路径。可复用对象优先独立场景，场景命名体现用途和生命周期。

推荐区分：启动/流程场景、关卡场景、实体场景、UI 场景和测试场景。一个场景只能有一个主要生命周期负责人。

## 2. Resource 与运行时状态

静态配置、物品定义、敌人配置、技能参数和关卡配置使用 `Resource` 或明确数据类。运行时生命、位置、库存、冷却、当前层等可变状态不能直接写回共享配置资源，避免实例之间污染。

## 3. 节点与信号

信号必须有语义明确的发送者、接收者和参数；禁止用一个信号承载多个无关事件。节点连接应尽量在场景组装或明确初始化阶段完成，并可在销毁时安全断开。

## 4. 资源路径

资源引用必须位于项目目录内，使用稳定的 `res://` 路径。不得把绝对本机路径、临时导出物、用户数据或密钥写入项目资源。
