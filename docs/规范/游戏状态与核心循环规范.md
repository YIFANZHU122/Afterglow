# 游戏状态与核心循环规范

## 1. 游戏流程

核心流程至少区分：启动、准备本层、探索、战斗、临时安全区、目标完成、Boss/结算、进入下一层、死亡、复活、局外成长和运行结束。状态转换必须有合法前置条件和失败路径，禁止用布尔变量集合隐式表达复杂流程。

## 2. 玩法边界

资源匮乏、驻留时间惩罚、迷雾刷新、安全区短期防护、分层地图、Boss 两路线解法和三档难度属于领域规则，修改它们必须按高风险任务处理并补回归测试。

## 3. 难度与复活

难度配置不应散落在玩家、地图和 UI 脚本中。复活次数、死亡终局、额外奖励和系统辅助由难度/运行会话模块统一决定，表现层只展示结果。

## 4. 局内与局外

局内资源和升级随本次运行变化；局外成长跨运行持久化。两者必须使用不同数据模型和存档边界，不能用清空几个字段的方式模拟完整重置。
