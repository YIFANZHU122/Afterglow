# 数据模型与接口契约规范

## 1. 公共接口必填项

新增或修改接口必须记录：名称、所属模块、输入类型、返回类型、前置条件、状态变化、错误/拒绝情况、调用方、测试、是否影响未来联机。

## 2. 状态与命令

建议将外部意图建模为命令，将结果建模为状态变化和事件。例如移动、使用物品、设置安全区、开始关卡目标、复活和进入下一层都应有明确入口，不由 UI 或节点路径直接改字段。

## 3. 数据边界

配置数据、运行时状态、存档数据和表现数据必须区分。共享数据使用明确 schema；不允许把任意 Dictionary 当作长期接口。字段删除、改名、类型变化或默认值变化均视为高风险。

## 4. 未来联机

当前不实现网络层，但核心命令和状态变化不能要求本地节点存在。输入可以替换为网络命令，状态变化可以由权威模拟产生，表现层只订阅结果。任何为联机预留的抽象必须说明成本和当前用途，禁止无需求过度设计。
