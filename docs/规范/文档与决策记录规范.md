# 文档与决策记录规范

## 1. 规范文件

根目录总规范是唯一入口；专项规范按职责拆分。规范文件自身的变更要说明原因、影响和版本变化，不把计划正文塞进索引。

## 2. 开发计划

正文路径：`docs/开发计划文档/计划NNN-计划名称.md`。索引路径：`docs/开发计划文档目录.md`。状态只能使用：`未开始`、`进行中`、`阻塞`、`已暂停`、`已完成`、`已取消`。

## 3. 决策记录

影响架构、接口、核心玩法、存档、依赖或未来联机的决定必须记录背景、选项、结论、理由、影响和回滚条件。决策发生变化时追加新记录，不抹掉历史结论。

## 4. 文档质量

禁止留下未解释的临时占位标记或“后续处理”作为验收结论。若确实未决定，必须明确列入阻塞或待决策项，并说明需要谁确认。
