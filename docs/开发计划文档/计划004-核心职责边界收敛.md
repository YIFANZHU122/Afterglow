# 计划004：核心职责边界收敛

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-22
- 完成日期：
- 负责人：项目维护者与 AI 协作

## 2. 目标

在保留现有玩法、场景节点、公共信号和 Autoload 名称的前提下，继续将库存、攻击资格、复活状态、物品交互输入和世界场景组装从玩家/场景脚本中收敛到职责明确、可测试的模块边界；当剩余代码只承担节点组装、命令分发和表现协调时停止本轮解耦。

## 3. 背景与问题

计划002已抽离生命/体力模型，计划003已抽离玩家本地输入。但 `player.gd` 仍同时处理库存操作、掉落实例化、武器资格判断、攻击表现、死亡/复活和出生点读取；`item_world.gd` 直接读取本地 `Input`；`Inventory` Autoload 同时承担状态规则和跨场景信号适配；两个世界脚本重复相同的玩家出生与相机边界组装。

## 4. 范围

### 包含

- 新增 `InventoryModel`，让 `Inventory` Autoload 只做生命周期和信号适配。
- 新增 `MeleeAttackModel`，集中武器类型/伤害资格判断。
- 新增 `ReviveModel`，建模死亡、等待复活、复活完成和重复请求拒绝。
- 新增 `InteractionInputAdapter`，移除 `ItemWorld` 对 `Input` 的直接依赖。
- 新增共享世界组装基类，收敛两个世界场景的出生点和相机边界逻辑。
- 更新玩家脚本、物品世界脚本、库存适配器、世界脚本、测试和任务报告。

### 不包含

- 不改变移动、攻击伤害、复活等待时间、库存容量、输入动作、资源 schema 或场景节点名称。
- 不新增网络代码、插件、Autoload 或外部依赖。
- 不引入万能管理器；不把 HUD、动画和节点路径塞进领域模型。

## 5. 设计与依赖方向

`InventoryModel`、`MeleeAttackModel`、`ReviveModel` 是纯规则对象；节点脚本负责调用并把结果映射为现有信号、动画或场景实例。`InteractionInputAdapter` 是 `Input` 到交互意图的唯一边界。世界场景基类只负责注入已有玩家和相机节点并设置场景配置，不实现关卡规则。

## 6. 接口契约

| 接口 | 模块 | 输入 | 输出/状态 | 失败处理 | 联机影响 |
|---|---|---|---|---|---|
| `InventoryModel.add_item/drop_selected/drop_all` | `items` | `ItemData` 或无 | 更新库存快照 | 空物品、满库存、空槽返回失败/空结果 | 可由权威模拟调用 |
| `MeleeAttackModel.can_attack(item)` | `combat` | `ItemData` | `bool` | 空物品、非剑、非正伤害返回 false | 可由权威模拟调用 |
| `ReviveModel.request()` | `progression` | 无 | `WAITING` 或拒绝 | 非死亡状态重复请求拒绝 | 可由会话规则调用 |
| `ReviveModel.complete()` | `progression` | 无 | `ALIVE` 或拒绝 | 非等待状态拒绝 | 可由权威模拟调用 |
| `InteractionInputAdapter.is_interact_pressed()` | `presentation/input` | 无 | `bool` | 无 | 本地适配，可替换为命令 |
