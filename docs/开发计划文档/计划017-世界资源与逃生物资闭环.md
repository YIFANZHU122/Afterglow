## 2. 目标

实现首个可玩的“探索资源 -> 收集逃生物资 -> 启动出口”闭环。地图不提供固定开局补给；生存资源预算随难度变化；逃生物资进入独立任务模型，不占背包槽位或负重；出口启动可被移动、受击或近敌中断并保留进度。

## 3. 范围

### 包含

- 资源预算纯模型：普通基线食物 9 单位、水 12 单位、额外应急储备 20%，应用 100%/95%/90% 难度丰富度。
- 逃生目标纯模型：三类基础物资和一类关键物资、每类显式数量、10 秒出口启动、进度保留和完成后消费。
- GameManager 组合逃生目标并提供命令、只读查询和状态信号；进入下一层重建本层目标，复活保留进度，重置/最终结束清空。
- 地下室灰盒放置远离出生点的任务物资，增加任务 HUD，并把出口改为收集完成后可启动。
- 保留现有石剑拾取、战斗、升级奖励和生存 HUD 回归。

### 不包含

- 正式随机地图生成、容器概率表和可达性图算法。
- 篝火燃料、净水、烹饪和食物腐败运行时；这些在后续独立计划中接入，数值继续使用总基线文档。
- 敌人进入出口范围的自动空间查询；首版领域模型与控制器保留明确的 `enemy_nearby` 中断输入。
- 新插件、外部依赖、Autoload、存档字段、网络代码或输入映射。

## 4. 设计决定

- 不扩充 `ObjectiveProgressModel`。击杀计数与多类别收集/启动属于不同状态机，新增 `EscapeObjectiveModel` 避免破坏现有遭遇契约。
- 任务物资使用枚举类型和显式方法，不使用任意 Dictionary，不创建背包 `ItemData`。
- 首版地下室需求固定为零件 2、燃料 2、布料 2、钥匙 1；后续地图生成器可在 2–4 范围内注入各基础需求。
- 难度资源数量使用四舍五入并至少保留 1 单位；应急储备按调整后的保底量向上取整 20%，防止小预算因取整丢失保底。
- 出口启动为按住交互键的连续命令；松开、移动、受击或近敌只暂停，不清零，也不提前消费物资。

## 5. 公共接口

### ResourceBudgetModel

- `get_guaranteed_food() -> int`
- `get_guaranteed_water() -> int`
- `get_emergency_food() -> int`
- `get_emergency_water() -> int`
- `get_total_food() -> int`
- `get_total_water() -> int`

### EscapeObjectiveModel

- `collect_material(material_type: int, amount: int = 1) -> bool`
- `get_required_amount(material_type: int) -> int`
- `get_collected_amount(material_type: int) -> int`
- `has_all_materials() -> bool`
- `advance_exit_startup(delta: float, player_moving: bool, was_hit: bool, enemy_nearby: bool) -> bool`
- `get_exit_startup_seconds() -> float`
- `is_exit_started() -> bool`
- `consume_for_departure() -> bool`

### GameManager

- 新增逃生物资收集、出口启动、任务状态查询和 `escape_objective_changed` 信号。
- UI 和拾取节点只能调用公开命令，不访问模型内部状态。

## 8. 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 现有击杀/升级出口流程与新逃生目标冲突 | 保留遭遇与奖励流程，出口额外要求逃生启动完成 | 移除地下室逃生控制器，恢复 TransitionZone 原门槛 |
| 任务物品误占背包或丢失 | 使用独立模型与专用拾取节点，不调用 Inventory | 移除专用节点，不迁移任何库存数据 |
| 10 秒交互在自动测试中易受帧序影响 | 领域模型用显式 delta 测试，场景只验证命令接线 | 保留模型，暂时退回按钮式启动表现 |
