# 计划040：翻越挖掘游泳与路线系统

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-31
- 任务分类：玩家移动能力、局部地形与路线核心规则
- 上级计划：`计划033-完整生存游戏开发总路线.md`
- 前置依赖：计划034至039完成

## 2. 目标

把 step 高度、水深和可挖地块转化为真实路线选择，让翻越、挖掘和游泳提供捷径、避战或资源机会，同时保证基础角色始终存在一条可通关路线。

## 3. 包含

- 统一 `40 px = 1 step` 的领域换算和高度/水深标签。
- 2 step 普通翻越、3 step 高位翻越、超过 3 step 禁止直接翻越。
- 可挖泥土、沙地、碎石和塌方地块，最多向下 3 step。
- 铲子耐久、挖掘耗时、体力、噪音、中断和局部地形快照。
- 0/1/2/3+ step 水深，涉水减速、游泳体力、挣扎和溺水缓冲。
- 负重、装备、天气和属性对三种能力的统一修正。
- 基础路线、能力路线和高风险资源路线标签。
- 地图验证拒绝越界、绕过出口、封死回程和唯一随机工具路线。

## 4. 不包含

- 不实现自由体素地形或任意位置挖掘。
- 不实现复杂坠落、攀岩、潜水或水下战斗。

## 5. 验收标准

- [x] 所有翻越、挖掘和游泳动作具备前置条件、中断、消耗和完成结果。
- [x] 地形变化影响碰撞、通行和积水，但不破坏地图主边界。
- [x] 体力归零和超重状态遵守挣扎、溺水和能力禁止规则。
- [x] 每个关键目标至少有一条无专用工具基础路线和一条能力路线。
- [x] 洪水或灾难不会永久封死唯一基础路线。
- [x] 地形状态、工具耐久和玩家动作状态正确保存恢复。
- [x] 标准验证与三类路线灰盒流程通过。

## 6. 风险

- Godot 2D 没有天然高度层，必须以显式领域标签驱动，不用 `z_index` 代替高度规则。
- 动态碰撞更新要限制范围，避免大地图性能抖动。
