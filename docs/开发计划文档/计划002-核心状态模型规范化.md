# 计划002：核心状态模型规范化

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-22
- 负责人：项目维护者与 AI 协作
- 任务分类：跨模块、中风险工程改造

## 2. 目标

将玩家生命和体力的核心规则从节点树、输入系统和表现层中抽离为可测试的领域模型，保留现有场景与公共组件调用方式，并为后续按目标模块目录迁移建立最小可用边界。

## 3. 范围

### 包含

- 新增 `HealthModel`，负责生命值、伤害、治疗、死亡和重置规则。
- 新增 `StaminaModel`，负责行走、奔跑、疲劳和体力恢复状态机。
- 让 `HealthComponent` 成为 `HealthModel` 的节点适配器，让玩家脚本只负责输入采集、移动和表现。
- 新增模型级 GDScript 测试，覆盖正常、边界、空/无效输入、重复调用和失败路径。
- 更新项目台账与本计划的执行、验证和交接记录。

### 不包含

- 不修改物品栏、场景切换、存档、Autoload、资源 schema 或玩法数值。
- 不一次性迁移全部源码到目标目录，不新增第三方依赖或网络层。
- 不修改 `word` 文件夹中的任何 SOP 或项目模板。

## 4. 影响模块与接口契约

| 接口 | 所属模块 | 输入/返回 | 前置条件与失败处理 | 调用方 | 联机影响 |
|---|---|---|---|---|---|
| `HealthModel.take_damage(amount)` | `combat` | `float` / `void` | `amount <= 0` 或已死亡时无状态变化 | `HealthComponent` | 可由权威模拟直接调用 |
| `HealthModel.heal(amount)` | `combat` | `float` / `void` | `amount <= 0` 或已死亡时拒绝；结果不超过上限 | `HealthComponent` | 可由权威模拟直接调用 |
| `HealthModel.reset()` | `combat` | 无 / `void` | 任意状态可调用，恢复满血并清除死亡 | `HealthComponent` | 可作为复活结果 |
| `StaminaModel.tick(delta, direction, sprint_requested)` | `player` | `float, Vector2, bool` / `void` | `delta <= 0` 时忽略；状态机不读取 Input 或节点 | `player.gd` | 输入可替换为网络命令 |
