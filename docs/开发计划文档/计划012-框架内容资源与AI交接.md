- 状态：已完成
- 创建日期：2026-08-23
- 完成日期：2026-08-23

## 2. 目标

将计划010 的灰盒框架从“可运行”推进到“可被其他 AI 稳定扩展”：区域配置外置为内容资源，静态内容具备契约校验，并形成可执行的 AI 开发手册。

## 3. 背景与问题

当前地下室的 AreaDefinition、EncounterDefinition 和 SpawnDefinition 嵌在 `basement.tscn` 内。它能运行，但后续 AI 若复制场景或修改子资源，容易造成资源路径不清、配置漏项和跨模块越界。项目已有 typed Resource 和模块边界，下一步应把内容创作流程显式化，并用自动校验降低接入成本。

## 4. 范围

### 包含

- 新增纯模型 `ContentValidationModel`，校验 Spawn、Encounter、Area、Upgrade 的现有公共契约。
- 将地下室区域配置外置为 `assets/areas/basement_area.tres`。
- 新增独立框架验证入口。
- 新增面向其他 AI 的完整框架使用指南和契约速查表。
- 更新 README 和计划索引。

### 不包含

- 不新增武器系统、技能树、随机奖励、导航、地图生成、存档、网络或正式美术管线。
- 不迁移现有 Area/Encounter 公共接口名称。
- 不清理计划001-011 的既有未提交文件。

## 6. 架构与设计方案

静态内容仍由 Resource 描述，运行时状态仍由模型、组件和 GameManager 持有。`ContentValidationModel` 只读 Resource 并返回错误数组，不实例化实体、不修改节点树、不写入存档。场景只负责引用 AreaDefinition 并把它交给 `EncounterController`；AI 手册围绕“先读规范、再改 Resource、最后跑验证”的流程组织。
