- 创建日期：2026-08-31

## 2. 总目标

将当前可运行灰盒推进为完整的 2D 俯视角生存 Roguelite，使资源有限、时间压力、夜晚迷雾、天气灾难、地图逃生和角色构筑形成统一的可玩闭环。

## 4. 执行原则

- 严格按依赖顺序推进，同一时间只允许一个主子计划处于“进行中”。
- 每个子计划必须产出独立可运行版本、任务报告和完整验证记录。
- 新系统优先落在独立领域模型，`GameManager` 只做协调和跨场景状态转发。
- 数值进入集中配置；每阶段完成后根据真实游玩结果调参，不靠一次性猜测锁死最终值。
- 后续子计划如果因前序接口变化需要调整，只能修改实施细节，不能悄然删除总目标和验收项。

## 5. 总体验验收

- [x] 玩家能从无固定补给开局，通过探索、采集、消费、制作和战斗维持生存。
- [x] 白天准备、夜晚迷雾、月相、天气、灾难和驻留超时共同形成递增压力。
- [x] 玩家可以技术和运气提前离开，也可以依靠防御延迟，但不能永久安全驻留。
- [x] 智力、力量、体力，装备、负重、Buff 和结晶成长相互独立且能共同构筑角色。
- [x] 六张地图具有真实玩法差异，所有关键目标存在基础可达路线和能力捷径。
- [x] Boss 双路线、死亡复活、整局失败、结算和退出恢复全部可靠。
- [x] 完整验证、长局测试、性能和存档兼容达到发布候选标准。

## 6. 当前执行入口

计划034至计划043均已完成并通过验收。本总路线已关闭，当前没有待启动的子计划；后续工作应以新的独立计划承接正式美术、内容扩充或发行平台适配。

## 7. 风险与控制

- 长路线的主要风险是同时修改过多核心模块；通过一个子计划一个验收版本控制影响范围。
- `GameManager` 已较大；新增规则不得直接堆入单文件，必要拆分包含在对应子计划内。
- 存档 schema 会持续增长；每阶段强制增加旧快照恢复和非法快照拒绝测试。
- 玩法内容可能在系统完成前显得稀薄；优先使用少量可复用灰盒资源验证循环，正式内容集中在计划042。
