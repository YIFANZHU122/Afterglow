# 计划034：物品库存与世界采集基础

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-31
- 任务分类：物品、库存、世界资源与存档核心规则
- 上级计划：`计划033-完整生存游戏开发总路线.md`
- 前置依赖：现有库存、交互、快照和难度模型
- 任务级实施计划：`docs/superpowers/plans/2026-08-31-item-inventory-gathering-foundation-implementation-plan.md`

## 2. 目标

建立后续食物、制作、装备、工具、武器和掉落共同使用的物品实例与库存基础，让玩家能在地图中采集有限资源并真实占用 8 格基础背包容量和重量。

## 3. 包含

- 扩展 `ItemData`：堆叠上限、单位重量、用途标签和稳定资源 ID。
- 新增运行时物品栈，保存定义 ID、数量、耐久和实例附加状态。
- 库存支持堆叠、拆分、移除、转移、8 格基础容量、重量统计和旧快照迁移。
- 新增可采集资源定义、运行时节点模型、交互场景和确定性产出。
- 首批资源：木材、石料、野生食物原料、基础零件。
- 地下室和慈航郊外接入有限资源节点，采尽后不会自动刷新。
- HUD 显示格子、数量、选中项和当前重量。

## 4. 不包含

- 不实现食用、饮水、疾病、容器和加工。
- 不实现配方、篝火、火把、建筑、装备栏和工具耐久消耗。
- 不实现随机地图生成；资源点使用确定性内容配置。

## 5. 接口与数据边界

- 静态物品使用 typed Resource，不在快照中复制显示文本和贴图。
- 运行时物品栈使用稳定定义 ID 恢复，未知 ID 导致该快照被拒绝。
- 基础库存容量固定为 8 格；计划039中的背包装备只能通过公开命令调整为 10 或 12 格。
- 难度不直接改变格子数，而是通过 `difficulty_resource_richness()` 调整地图资源总量。
- 世界资源节点保存稳定实体 ID、剩余操作次数和已耗尽状态。
- `Inventory` Autoload 继续作为跨场景库存服务，但规则委托给独立模型。

## 6. 验收标准

- [x] 同类物品优先合并至堆叠上限，剩余数量进入新格；空间不足时操作原子失败。
- [x] 无背包角色固定使用 8 格容量，数字键和 HUD 完整支持 1 至 8 格。
- [x] 普通/困难/地狱按 1.00/0.95/0.90 的资源丰富度生成可采集总量。
- [x] 重量按物品数量正确计算，非法数量、负重量和未知定义被拒绝。
- [x] 玩家可采集四类资源，资源耗尽、背包满和重复交互都有清晰结果。
- [x] 离层和安全退出恢复库存数量、选中格、重量和资源节点状态。
- [x] 现有石剑、掉落、死亡和场景切换行为保持兼容。
- [x] 标准验证与自动化采集流程通过。

## 7. 风险

- 当前快照复制完整 `ItemData` 字段，迁移为 ID 恢复时必须保留旧版本兼容。
- 容量调整可能影响现有五格 HUD 和数字快捷键；场景测试必须覆盖最长容量。
- 世界节点必须使用稳定 ID，不能依赖运行时节点名或数组顺序恢复。
