# 计划021：完整运行快照恢复集成

## 1. 基本信息

- 状态：进行中
- 创建日期：2026-08-28
- 任务分类：跨模块核心存档、场景实体恢复与安全退出集成
- 设计依据：现有 `RunSnapshotData` 固定 11 分区 schema，以及计划019建立的安全退出/边界回退规则

## 2. 目标

让安全退出存档真正覆盖并恢复当前运行所需的全部运行时状态：运行会话、随机流、生存、Boss、逃生目标、灾难、玩家、敌人、库存、建筑和交互。恢复过程必须先完成完整校验，再一次性提交，失败时不污染当前内存运行。

## 3. 范围

### 包含

- 为玩家、敌人和可恢复世界实体建立显式快照适配接口。
- GameManager 创建/恢复 11 个固定分区，并接入当前场景实体状态。
- 安全退出后重置内存对象，再恢复运行和实体状态。
- 局外结晶独立持久化，避免与局内运行快照混淆。
- 补充正常、边界、空数据、重复恢复、暂停、非法分区、损坏存档和结算后不可恢复测试。

### 不包含

- 不修改现有生存、灾难、Boss、背包或随机流规则。
- 不改变 `RunSnapshotData` 顶层 schema 版本和 11 个分区名称。
- 不新增插件、输入映射、网络同步或万能 Autoload。
- 不实现跨版本迁移；schema 版本不匹配仍拒绝恢复。

## 4. 设计决策

1. 领域模型继续由各自模型负责 `create_snapshot/restore_snapshot`；节点脚本只提供显式、稳定的场景实体适配方法。
2. GameManager 通过当前场景的明确分组和方法契约收集实体，不直接依赖具体节点路径；缺少可恢复接口的装饰性节点不写入运行状态。
3. 恢复采用“两阶段”：先在临时模型和临时实体数据上验证所有分区，再替换 GameManager 运行模型；任何失败都返回 `false` 并保持原状态。
4. 玩家位置、朝向、生命、体力和死亡表现属于 `player_state`；敌人实例使用稳定实体 id、位置、生命、速度、攻击冷却和击败状态；建筑/交互分别保存可变激活、拾取和进度状态。
5. 局外结晶使用独立本地文件，不进入局内快照，胜利/失败结算后仍保留。

## 7. 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 现有场景实体没有稳定 id | 由场景实例名加同组序号生成并在恢复时严格匹配 | 仅恢复领域模型，保留实体默认场景状态 |
| 恢复过程中实体节点已被场景重建 | 两阶段先校验，再按 id 应用；缺失实体拒绝恢复 | 回退到安全边界存档 |
| 局外存储污染测试环境 | 使用独立 user 路径并提供清理辅助 | 删除新增 meta 文件，不影响运行快照 |
| 工作区存在大量未提交修改 | 只增量编辑本计划涉及文件，不覆盖他人内容 | 保留现有修改并暂停本计划 |
