## 2. 目标

把计划014/015中已经存在的灾难概率模型推进为可观察、可反制的运行时闭环：灾难先预警再生效；敌人受视觉、声音和脱战规则约束；迷雾刷新受威胁预算与保护区限制；玩家可以从 HUD 看见当前灾难、倒计时、风险和主应对设施状态。

## 3. 范围

### 包含

- `ThreatBudgetModel`：按驻留日/超时阶段计算普通、特殊和精英威胁预算，支持并发灾难临时预算，拒绝超预算生成。
- `SpawnProtectionModel`：入口、出口、出生点、篝火、任务物资和玩家周边保护区判定；刷新点要求处于迷雾、不可见且距离玩家至少 8 step。
- `EnemyPerceptionModel`：视觉、听声调查、线索更新、8 秒开始降确信度、普通怪最迟 15 秒转搜索。
- `DisasterEventModel`：预警 10 秒、普通灾难 120–240 秒、困难灾难 240–360 秒；唯一主应对和完成状态；同类不可并发。
- `GameManager` 灾难生命周期、事件信号和只读 HUD 查询；实际灾难每 60 秒根据既有 `DisasterSchedulerModel` 生成。
- `ChaserEnemy` 改为使用感知模型：失去线索后前往调查点，脱战后停止锁定，不读取玩家实时坐标作为永久锁定。
- 地下室加入最小预警 HUD 和一个可交互的“信号抑制器”灰盒主应对设施，用于验证困难灾难流程；不把所有灾难表现硬编码进敌人脚本。

### 不包含

- 正式随机地图生成、导航网格、墙体声学烘焙和复杂路径寻找。
- 四类困难灾难的正式地形改造；本轮以统一事件模型、预警和设施交互证明闭环，山洪/毒雾等效果以状态字段表达。
- Boss、存档随机流、网络同步、插件、外部依赖和输入映射变更。
- 将所有怪物升级为完整行为树；只改造现有追击型敌人的感知边界。

## 4. 设计决定

- 以 `step` 作为领域距离单位；当前灰盒约 40 像素/step，模型不依赖像素换算。
- 视觉发现默认要求目标在视野内且无遮挡；首版不实现射线遮挡，调用方显式传入 `has_line_of_sight`。
- 听声线索只保存发生位置与剩余有效时间，不保存玩家实时坐标；枪声/近战/施工声统一由调用方注入半径和强度。
- 灾难预警不直接扣血；生效后的具体环境效果通过 `DisasterEventModel` 状态和现有生存系统消费。普通灾难没有唯一解，困难灾难只有一个主应对设施。
- 预警期间仍推进生存时钟和灾难概率；暂停游戏会冻结灾难事件进度。

## 5. 公共接口

### ThreatBudgetModel

- `get_base_budget(day_index: int, overtime_stage: int) -> int`
- `get_active_budget(disaster_bonus_ratio: float = 0.0) -> int`
- `can_spawn(cost: int, used_budget: int) -> bool`
- `register_spawn(cost: int) -> bool`
- `release_spawn(cost: int) -> bool`
- `get_used_budget() -> int`

### SpawnProtectionModel

- `is_protected(candidate: Vector2, player_position: Vector2, protected_points: Array[Vector2], is_visible: bool, in_fog: bool) -> bool`
- `is_valid_spawn(candidate: Vector2, player_position: Vector2, protected_points: Array[Vector2], is_visible: bool, in_fog: bool) -> bool`

### EnemyPerceptionModel

- `observe_visual(player_position: Vector2, has_line_of_sight: bool, brightness: float, required_brightness: float) -> bool`
- `hear_sound(sound_position: Vector2, radius: float, sound_strength: float) -> bool`
- `advance(delta: float) -> bool`
- `get_state() -> int`
- `get_last_known_position() -> Vector2`
- `get_confidence() -> float`

### DisasterEventModel

- `start_warning(kind: int, elapsed_seconds: float) -> bool`
- `advance(delta: float, countermeasure_progress: float = 0.0) -> bool`
- `interrupt_countermeasure() -> bool`
- `complete_countermeasure() -> bool`
- `get_phase() -> int`
- `get_remaining_seconds() -> float`
- `is_active() -> bool`
- `is_resolved() -> bool`

## 8. 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 感知模型改变现有追击行为 | 先以默认视觉锁定兼容当前灰盒，再在失去线索后进入调查/搜索 | 恢复 ChaserEnemy 原追击入口，保留模型供后续接入 |
| 灾难事件和生存 tick 时序竞争 | GameManager 统一推进并发出只读事件，场景不直接修改模型 | 暂停实际灾难生成，只保留预警状态 |
| 保护区校验阻止合法灰盒生成 | 仅由 EncounterController 在生成前调用，失败项记录原因并不计入预算 | 暂时关闭新增刷新点，保留原固定遭遇 |
