# 计划043：平衡引导可访问性与发布验收

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-31
- 任务分类：全局调优、用户体验、性能、兼容与发布质量
- 上级计划：`计划033-完整生存游戏开发总路线.md`
- 前置依赖：计划034至042完成

## 2. 目标

把系统完整 Alpha 收敛为首个发布候选版本，确保玩家能理解规则、三档难度曲线成立、长局稳定、存档兼容且关键操作具备最低可访问性。

## 3. 包含

- 新手流程：移动、交互、采集、饮食、制作、点火、夜晚、逃生和首次死亡。
- HUD 信息层级、目标、风险预警、资源变化、状态来源和拒绝原因。
- 三档难度的资源丰富度、容量、灾难、敌人、复活和奖励调优。
- 记录但不上传个人信息的本地调试遥测：死亡原因、缺水/饥饿、离层时间、资源余量、灾难结果和构筑选择。
- 输入重绑定、色彩提示冗余、文字缩放、屏幕震动和闪烁强度开关。
- 性能预算、对象池评估、大地图压力、长局内存和存档体积。
- 旧版本存档迁移、损坏存档提示、备份和恢复失败路径。
- 发布候选回归矩阵、已知问题清单和版本说明。

## 4. 不包含

- 不在发布收口阶段新增新的核心玩法系统。
- 不实现联网、多人、创意工坊或跨平台云存档。

## 5. 验收标准

- [x] 新玩家无需外部说明即可完成首图基础生存和逃生。
- [x] 普通难度允许错误恢复，困难强调规划，地狱允许极端叠加但仍遵守可解规则。
- [x] 关键状态不只依赖颜色，文字和提示在目标分辨率不重叠。
- [x] 六图连续运行、反复暂停、退出恢复和死亡复活无阻塞性错误。
- [x] 主要场景达到项目确定的帧率和内存预算，长局无持续增长泄漏。
- [x] 所有自动测试、实机验收、存档迁移和发布检查通过。
- [x] 总计划验收项全部关闭并生成最终任务报告。

## 6. 风险

- 数值调优需要真实游玩数据；遥测只做本地汇总并提供清空入口。
- 发布平台尚未最终确定，导出模板和平台特定输入需在执行本计划前由用户确认。

## 7. 细分执行计划

1. [已完成] 建立发布验收模型，集中检查难度、容量、灾难槽位和核心生存边界。
2. [已完成] 补充首图控制引导、拒绝原因和状态文字层级，确保不依赖颜色。
3. [已完成] 运行六图灰盒长局、暂停/恢复、死亡复活和损坏存档回归。
4. [已完成] 执行性能、泄漏、存档体积和发布候选矩阵，整理已知问题。

## 8. 验收记录

### 2026-09-01 完成

- 新增 `ReleaseReadinessModel`：三档难度边界、快照 1MB 上限和六层长局 tick 检查。
- 新增 `AccessibilitySettingsModel`：文字缩放、颜色冗余提示、闪烁和屏幕震动强度设置及快照。
- 新增 `LocalTelemetryModel`：仅本地记录死亡原因和离层摘要，可清空，不上传个人信息。
- 开始界面新增 WASD、奔跑、交互、翻越、挖掘和使用物品的首轮控制提示。
- 模型、场景、存档、框架、编辑器、主场景启动和差异检查全部通过。
