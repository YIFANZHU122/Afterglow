# 计划013：生存数值基线文档化

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-27
- 完成日期：2026-08-27
- 负责人：Afterglow AI 协作

- 关联任务/问题：集中记录生存、天气、灾难、篝火、迷雾、月相、背包、敌人生态、Boss、存档和随机性规则

## 2. 目标

建立一份可作为单一策划参考的生存数值基线文档，并区分已确认规则、首版推荐值与待验证参数。

## 3. 背景与问题

原有玩法草案包含大量数值，但分散在对话和概念描述中，存在单位、时间尺度、资源口径和叠加规则难以追踪的问题。若直接进入实现，后续调试会出现重复常量和规则解释不一致。

## 4. 范围

### 包含

- 时间、天气、灾难、难度、资源、生存值和加工参数。
- 篝火、复活点、照明、迷雾、月相和敌人压力参数。
- 背包、容器、负重、疾病和治疗参数。
- 普通/困难灾难目录、反制方式和并发公平保底。
- 敌人职责型 AI、威胁预算、掉落上限和第 6 图 Boss 双路线。
- 暂停、自动保存、退出恢复、确定性随机、难度锁定和最低可访问性语义。
- 首版调参顺序、测试记录字段和待验证项。

### 不包含

- GDScript、场景、Resource schema 或存档字段修改。
- 正式地图生成、敌人 AI、制作配方和 UI 实现。
- 将暂定数值直接写入运行时代码。

## 6. 架构与设计方案

使用“规则解释 + 参数表 + 状态标记”的文档结构。规则说明固定玩家体验边界，参数表提供调试入口，状态标记防止把首版推荐值误当成永久定案。后续代码接入时，应让领域模型读取集中配置或等价常量，并以参数名保留测试断言语义。

## 7. 接口与数据变化

无代码接口、Resource schema、存档字段或网络边界变化。
