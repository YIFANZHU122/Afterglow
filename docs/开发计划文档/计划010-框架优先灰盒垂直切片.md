# 计划010：框架优先灰盒垂直切片

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-23
- 任务分类：跨模块、数据定义、战斗遭遇、局内构筑和场景流程改造
- 设计文档：`docs/superpowers/specs/2026-08-23-framework-first-graybox-design.md`

## 2. 目标

在正式玩法和美术未确定时，完成一条可玩的、可测试、可替换内容的灰盒垂直切片：区域配置驱动遭遇生成，玩家完成战斗目标后选择局内强化，之后才允许清除区域并进入下一场景。

## 3. 范围

### 包含

- `EncounterSpawnDefinition`、`EncounterDefinition`、`AreaDefinition` Resource。
- `EncounterMember` 统一击败事件和奖励发放契约。
- `EncounterController` 负责从区域配置生成敌人并维护目标进度。
- `RunBuildModel` 与 GameManager 局内伤害/移速强化接口。
- 灰盒奖励选择面板，限制在目标完成状态提交一次。
- 玩家和追击敌人的最小 Presentation 语义边界。
- 地下室改为配置驱动生成两个敌人，并补完整场景回归。

### 不包含

- 程序化地图、导航网格、复杂 AI 状态树。
- 完整武器库、技能树、状态效果、局外成长和存档。
- 正式美术资源、导入工具和发布平台适配。
- 网络同步或无当前用途的联机抽象。

**依赖：** 任务 2、任务 3。

- 新增 `scripts/presentation/graybox_actor_presenter.gd`

**验收：** Presentation 缺失只警告不阻断玩法；玩家攻击、敌人受击、死亡、奖励选择、区域清除、重置均有场景回归覆盖。

**实现说明：** 灰盒 Presenter 仅包含一个脚本节点，没有为单节点包装额外场景；玩家和追击敌人直接注入脚本节点，减少无收益的场景层级。

## 5. 执行顺序

严格按任务 1 → 2 → 3 → 4 执行。每完成两个任务执行一次模型测试、场景测试和 Godot 编辑器扫描；全部任务完成后执行完整验收。

## 6. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 配置生成改变现有场景实例顺序 | 高 | 先保持节点名称和玩家/出口路径兼容，场景测试覆盖加载和目标数量 |
| 奖励选择与旧 FLOOR_CLEAR 状态不一致 | 高 | 面板提交只调用 GameManager 公共接口，出口继续以状态查询为准 |
| 表现边界迁移导致灰盒显示丢失 | 中 | 先建立 Presenter 语义接口，再替换一个实体并做可见冷启动 |
| 玩法尚未确定导致过度设计 | 高 | 第一阶段拒绝随机权重、技能树、存档和多路线策略 |

## 7. 验收标准

- [x] 冷启动地下室可玩，敌人由配置生成而非场景固定实例。
- [x] 玩家真实攻击和敌人真实接触伤害可用。
- [x] 击杀目标完成后奖励面板出现，选择强化后倍率生效。
- [x] 选择奖励前出口锁定，选择后区域清除并可切换场景。
- [x] 新局重置清除本局升级。
- [x] 模型测试、场景回归、编辑器扫描、主场景启动和 diff 检查通过。
- [x] 任务报告记录修改文件、接口、测试结果和遗留风险。
