# 计划005：本局运行会话与楼层流程基础

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-23
- 任务分类：跨模块、高风险核心规则改造
- 目标版本：Godot 4.7.1、GDScript

## 2. 目标

建立 Afterglow 的最小本局运行会话状态机，明确启动、准备楼层、探索、目标完成、进入下一层、死亡和运行结束的合法转换，并接入现有 `GameManager`，为后续敌人、关卡目标、Boss、奖励和局外成长提供稳定入口。

## 3. 本轮范围

### 包含

- 新增无节点依赖的 `RunSessionModel`。
- 为状态转换定义显式命令方法、状态查询和拒绝语义。
- `GameManager` 管理当前本局会话，并暴露开始本局、准备楼层、完成目标、进入下一层、标记死亡和结束本局接口。
- 保留现有场景切换行为；传送成功只负责切换场景，不自动跳过会话状态契约。
- 补模型测试、Autoload 初始化和主场景无头验证。

### 不包含

- 敌人 AI、刷怪器、Boss、安全区、迷雾和程序化地图。
- 局内升级、局外成长、存档和第三方依赖。
- 修改现有物品栏、玩家移动、攻击数值和公共场景节点结构。

## 4. 状态与接口契约

状态：`IDLE`、`PREPARING_FLOOR`、`EXPLORING`、`OBJECTIVE_COMPLETE`、`FLOOR_CLEAR`、`DEAD`、`RUN_ENDED`。

公开方法：

- `start_run()`：仅 `IDLE` 可调用，进入 `PREPARING_FLOOR`，楼层设为 1。
- `prepare_floor()`：仅 `PREPARING_FLOOR` 可调用，进入 `EXPLORING`。
- `complete_objective()`：仅 `EXPLORING` 可调用，进入 `OBJECTIVE_COMPLETE`。
- `clear_floor()`：仅 `OBJECTIVE_COMPLETE` 可调用，进入 `FLOOR_CLEAR`。
- `start_next_floor()`：仅 `FLOOR_CLEAR` 可调用，楼层递增并进入 `PREPARING_FLOOR`。
- `mark_dead()`：仅运行中状态可调用，进入 `DEAD`。
- `revive()`：仅 `DEAD` 可调用，恢复死亡前的运行状态。
- `end_run()`：仅 `DEAD` 或 `FLOOR_CLEAR` 可调用，进入 `RUN_ENDED`。
- `reset()`：任意状态可调用，清回 `IDLE` 和楼层 0。

非法状态调用返回 `false` 且不修改状态；合法调用返回 `true`。模型不依赖 Input、节点树、UI 或 Autoload。
