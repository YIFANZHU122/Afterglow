# 计划005：时间与季节昼夜系统

## 1. 基本信息

- 状态：已完成
- 创建日期：2026-08-23
- 完成日期：2026-08-23
- 负责人：项目维护者与 AI 协作
- 任务分类：跨模块、高风险功能与存档扩展

## 2. 目标

新增一个职责单一的全局时间服务，持续管理小时、分钟、日期和季节，在场景切换后保持状态；为玩家提供易读的右上角 HUD，并以可见性优先的颜色调制统一表现昼夜。

## 3. 范围

### 包含

- 注册 `TimeManager` Autoload，默认时间为 `06:00 AM · 春 · 第1天`。
- 以现实一秒推进五个游戏分钟，四季循环且每季 28 天；暂停时停止推进。
- 以 `user://time_state.cfg` 保存小时、分钟、日期和季节，启动恢复、每 60 秒自动保存、场景切换和窗口关闭时保存。
- 通过语义明确的时间、日期、季节和光照信号连接表现层。
- 新增时间 HUD 场景并注入既有玩家 `HUD` CanvasLayer。
- 对当前世界根节点创建或更新 `DayNightModulate`，完成黎明、白天、黄昏和夜间的连续调色。
- 添加可重复运行的时间边界模型测试与任务文档。

### 不包含

- 不新增天气、农作物、NPC 作息、季节资源或真实世界时钟同步。
- 不改变玩家移动、战斗、库存、输入动作、已有世界节点和场景切换语义。
- 不引入网络层、插件、外部依赖或通用业务管理器。

## 4. 架构与依赖

`TimeManager` 是唯一的跨场景时间状态和时间存档所有者。它只维护时间规则、持久化、时间事件和世界调色节点；不读取玩家状态、不决定 HUD 布局，也不保存到场景节点。`TimeDisplay` 是纯表现组件，仅订阅 `time_changed` 并读取只读格式化数据。`GameManager` 在场景替换前调用公开保存入口，避免切换窗口内丢失最近状态。

依赖方向为：`TimeManager 状态变化 -> 时间/光照信号 -> HUD 或当前世界表现`；`GameManager -> TimeManager.save_state()`。HUD 位于 `CanvasLayer`，不受世界 `CanvasModulate` 影响。

## 5. 接口与数据契约

| 名称 | 所属模块 | 输入 | 输出/状态变化 | 前置条件与失败处理 | 调用方/联机影响 |
|---|---|---|---|---|---|
| `TimeManager.get_hour/get_minute/get_day/get_season` | core 时间服务 | 无 | 返回当前只读状态 | 无 | HUD、后续规则；可由权威模拟提供 |
| `TimeManager.get_time_text/get_date_text` | core 时间服务 | 无 | 返回本地化显示字符串 | 无 | `TimeDisplay`；表现层只读 |
| `TimeManager.set_time` | core 时间服务 | 合法或任意整数 | 规范化时间并发出相关信号 | 超界值钳制到有效范围 | 调试/测试；未来需由会话授权调用 |
| `TimeManager.save_state/load_state` | core 时间服务 | 无 | 读写 `user://time_state.cfg` | 读写失败或非法字段回退默认值，不阻断启动 | 生命周期、`GameManager`；单机本地存档 |
| `time_changed/day_changed/season_changed/lighting_changed` | core 时间服务 | 类型化时间或颜色 | 通知状态变化 | 只由 `TimeManager` 发出 | HUD、世界表现；网络层未实现 |

存档 schema 为 `[time]` 下的 `hour`、`minute`、`day` 和 `season` 四个整数。其与玩家、物品或场景 Resource 数据隔离；缺失、损坏或类型不符时回退 `06:00 / 春第1天`。

## 8. 风险与回滚

| 风险 | 缓解 | 回滚条件与方式 |
|---|---|---|
| 时间存档与未来存档系统冲突 | 独立、最小化的 ConfigFile schema，加载时严格校验 | 未来统一存档服务确定后，迁移字段并保留兼容读取 |

| 场景切换遗漏最新状态 | 切换前显式保存且每 60 秒备份 | 移除 `GameManager` 保存调用，不影响既有切换功能 |
| 全局服务职责膨胀 | 限定为时间、存档、时间事件与世界调色 | 天气、NPC、作物等需求另立计划和模块 |
