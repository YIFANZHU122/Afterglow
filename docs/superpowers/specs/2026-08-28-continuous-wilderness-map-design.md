# 连续荒野地图与环境碰撞设计

## 1. 背景

当前慈航郊外已经具备较大的场景边界和相机跟随，但内部环境主要是背景贴图/多边形表现，缺少可阻挡玩家和敌人的真实碰撞。用户希望在保留单张连续地图的前提下扩大地图，并加入草原、森林、荒漠等荒野末日地形。

## 2. 目标

1. 将慈航郊外扩展为一张连续的 `5760×3240` 大型地图。
2. 在同一张地图内布置荒草平原、枯树林地、荒漠废墟三个连续分区，并提供自然过渡带。
3. 将树群、岩石、倒木、废弃车辆和残墙制作成带真实碰撞形状的可复用环境资源。
4. 保留现有地下室入口、地图出口、玩家出生、敌人、寄生花和存档/地图切换语义。
5. 让玩家和敌人在障碍物处受到物理阻挡，同时保持地形之间至少两条横向可通行路线。

## 3. 非目标

- 不拆分为多个地形场景，不新增运行时随机地图生成。
- 不改写玩家移动、攻击、敌人感知、灾难、存档或地图流程规则。
- 不新增插件、Autoload、外部依赖或网络同步。
- 不把草地、沙地和土路制作成不可通行区域；地形表现与阻挡障碍分离。

## 4. 方案比较

### 方案 A：场景化地形与 `StaticBody2D` 障碍物（采用）

使用现有 Godot 场景结构，以 `Polygon2D`/`Line2D` 表现地形，以可复用 `StaticBody2D` 场景承载障碍碰撞。坐标固定、加载简单、存档复现稳定，适合当前灰盒到正式内容的过渡。

### 方案 B：TileMapLayer 物理地形

长期编辑效率和地形绘制能力更好，但需要建立 TileSet、物理层和素材图集，改动面大，当前没有现成地形图集，无法快速验证既有流程。

### 方案 C：运行时程序化生成

可提供更高随机性，但会引入地图种子、障碍快照和生成失败恢复等额外边界，当前存档与内容契约不需要这类复杂度。

采用方案 A，后续如果地形内容规模显著扩大，可以在不改变障碍资源契约的前提下迁移表现层到 TileMapLayer。

## 5. 地图布局

### 5.1 尺寸与坐标

| 项目 | 数值 |
|---|---:|
| 视口 | `1280×720` |
| 慈航郊外地图 | `5760×3240` |
| 外围墙厚度 | `40 px` |
| 可探索内边界 | `x=40..5720, y=40..3200` |
| 地形过渡带 | 每条约 `300~500 px` |

地图中心为 `(2880, 1620)`。玩家从地下室进入后位于西侧安全通道，默认出生点位于中央草原附近，地图出口位于东侧荒漠废墟边缘。

### 5.2 地形分区

- **西部荒草平原**：约 `x=40..2200`。低矮草色、枯草线条、少量孤立岩石和残旧路标，作为开局熟悉区。
- **中部枯树林地**：约 `x=1900..4200`。稀疏到中密度的枯树、倒木和灌木群，形成可辨认的弯曲通道。
- **东部荒漠废墟**：约 `x=3800..5720`。沙丘、裸岩、废弃车辆和残墙，整体更开阔，提供绕行路线。
- 分区重叠部分只负责颜色、植被和地表细节过渡，不叠加整块阻挡碰撞。

### 5.3 通行约束

- 从西向东至少保留一条北侧通路和一条南侧通路。
- 入口、出口、玩家出生点、寄生花和关键交互点周围保留至少 `160 px` 的无障碍缓冲区。
- 障碍物之间的主要通道宽度不低于 `128 px`，避免玩家碰撞体卡在拐角。

## 6. 环境资源与碰撞

### 6.1 资源边界

新增三个可复用场景，根节点均为 `StaticBody2D`，默认位于环境阻挡层：

- `scenes/objects/wilderness_tree/wilderness_tree.tscn`
- `scenes/objects/wilderness_rock/wilderness_rock.tscn`
- `scenes/objects/wilderness_wreck/wilderness_wreck.tscn`

每个场景只负责自身的视觉和碰撞，不修改玩家、敌人或关卡状态。实例可通过位置、缩放和颜色变化形成多种变体。

### 6.2 碰撞约定

- 环境障碍 `collision_layer = 1`，让玩家和敌人可以在同一物理层被阻挡。
- 玩家保留现有 `collision_mask = 3`；敌人保留现有追击和攻击层设置。
- 树群使用圆形或胶囊形碰撞，岩石使用矩形/圆形碰撞，废车和残墙使用长方形碰撞。
- 视觉多边形可以比碰撞形状大，但碰撞形状必须覆盖实际不可穿越的主体，不能只有贴图没有物理体。
- 外围四面墙继续使用 `StaticBody2D`，并与相机边界保持 `40 px` 约定。

### 6.3 视觉层级

慈航郊外新增 `CihangTerrainArt` 节点，放在玩家和敌人表现之后、环境天气 Presenter 之前或按现有层级约定置于背景层。地形底色、过渡带和道路属于表现层；障碍场景自身的视觉节点随障碍实例渲染。

## 7. 数据流与场景接入

1. `CihangOutskirts` 场景加载固定地图尺寸和外围墙体。
2. `CihangTerrainArt` 绘制三个分区、过渡带和主通道。
3. 障碍场景作为 `CihangOutskirts` 的直接子节点实例化，拥有独立的 `StaticBody2D` 碰撞。
4. `WorldSceneController` 继续读取 `_get_world_size()` 设置相机边界，不向玩家脚本注入地图细节。
5. 现有玩家、敌人、寄生花、环境 Presenter 和地图切换节点保持原有名称与公共接口。

## 8. 测试设计

### 场景回归

- 慈航郊外地图边界为 `5760×3240`，相机可移动范围大于视口。
- `CihangTerrainArt` 存在草原、森林、荒漠三个分区节点。
- 场景中至少存在三类环境障碍，并且每类都包含 `StaticBody2D` 和有效 `CollisionShape2D`。
- 玩家出生点、地下室入口、出口和寄生花不位于障碍碰撞范围内。
- 玩家从障碍物外侧向障碍物移动时，位置不会穿过障碍物；沿通道移动仍可继续前进。
- 现有敌人、拾取、灾难、存档恢复和地图切换测试继续通过。

### 失败路径与边界

- 空障碍场景或缺少碰撞形状时，框架/场景测试必须失败并给出明确节点名称。
- 障碍物误放到出生安全区时，场景测试必须失败。
- 入口或出口被完全封死时，通行测试必须失败。

## 9. 可调参数记录

首版固定记录以下可调值，后续通过文档和场景资源调整，不散落到玩家脚本：

- 地图尺寸：`5760×3240`
- 分区边界：`2200 / 4200`，过渡带约 `300~500 px`
- 障碍主体最小间距：`128 px`
- 关键点无障碍半径：`160 px`
- 外围墙厚度：`40 px`

## 10. 验收结论

设计批准后，下一步创建开发计划，先写失败测试，再按“地形表现 → 可复用障碍 → 地图接入 → 碰撞回归 → 全量验证”的顺序实现。
