- 开发计划：[计划021-完整运行快照恢复集成](../开发计划文档/计划021-完整运行快照恢复集成.md)

## 2. 完成内容

- `RunSnapshotData` 的既有 11 个分区保持不变，GameManager 现在实际写入玩家、敌人、建筑和交互分区。
- 玩家恢复位置、速度、朝向、生命、体力、复活状态和碰撞状态；追击敌人恢复位置、速度、生命、攻击冷却、感知线索和击败状态；训练人偶恢复生命、计时器和碰撞/可见性。
- 逃生物资拾取 id、抑制组件隐藏状态、环境装置激活状态作为交互分区保存，并在场景重建后按稳定节点名回填。
- GameManager 恢复改为先校验所有领域模型、实体分区、灾难事件和库存，再提交运行模型；重复恢复和非法分区被拒绝。
- 局外结晶写入独立 `user://afterglow_meta.json`，不与局内运行快照混合，胜利/失败结算后仍保留。
- 终局 Boss 场景增加从 GameManager 同步 HealthComponent 的恢复适配。

## 4. 接口与数据变化

- 新增节点快照接口：`create_snapshot() -> Dictionary`、`restore_snapshot(snapshot: Dictionary) -> bool`，仅用于显式运行实体适配。
- 新增 `GameManager.register_runtime_scene(scene: Node) -> bool`、`apply_pending_scene_state(scene: Node) -> bool` 和 `record_escape_material_entity(entity_id: String) -> bool`。
- 新增 `HealthModel`、`HealthComponent`、`StaminaModel`、`ReviveModel`、`EnemyPerceptionModel` 的快照接口。
- 未修改 `RunSnapshotData` schema 版本、顶层分区名称、输入映射、网络边界或生存/灾难/Boss规则。
- 局外结晶采用独立版本化文件 `{schema_version, meta_crystals}`。

- 当前恢复只接受同一 schema 版本，旧版本不会自动迁移。
