# 报告005：本局运行会话与楼层流程基础

## 1. 任务分类与计划

- 任务类型：跨模块、高风险核心规则改造
- 开发计划：`docs/开发计划文档/计划005-本局运行会话与楼层流程基础.md`
- 最终状态：已完成

## 2. 修改与新增文件

- 新增 `scripts/core/run_session_model.gd`：无节点依赖的本局运行状态机。
- 修改 `scripts/autoload/game_manager.gd`：持有会话模型，提供本局生命周期接口和 `run_state_changed` 信号。
- 修改 `scripts/world/world_scene_controller.gd`：首次世界场景加载时将会话从空闲推进到探索。
- 修改 `tests/run_model_tests.gd`：补充运行会话正常流程、非法调用、重复调用、死亡、终局和重置测试。
- 新增 `docs/开发计划文档/计划005-本局运行会话与楼层流程基础.md`。
- 修改 `docs/开发计划文档目录.md`，新增计划005并同步为已完成。

## 3. 接口与数据变化

`RunSessionModel` 新增状态：`IDLE`、`PREPARING_FLOOR`、`EXPLORING`、`OBJECTIVE_COMPLETE`、`FLOOR_CLEAR`、`DEAD`、`RUN_ENDED`。

新增方法：`start_run()`、`prepare_floor()`、`complete_objective()`、`clear_floor()`、`start_next_floor()`、`mark_dead()`、`end_run()`、`reset()`、`get_state()`、`get_floor_number()`。

`GameManager` 新增同名本局生命周期包装接口、`get_run_state()`、`get_floor_number()`、`is_run_idle()`、`is_preparing_floor()` 和 `run_state_changed(state, floor_number)`。原有 `change_scene()`、`can_transition()` 和出生点行为未修改。

## 5. 风险与遗留问题

- 当前状态机只提供流程基础，尚未将敌人、目标、安全区、Boss 和胜负 UI 接入状态转换。
- 玩家现有复活按钮仍是独立表现流程，本轮未改变复活次数、死亡惩罚或终局规则。
- `GameManager` 仍为 Autoload；后续扩展必须维持清晰职责并补独立计划。

## 6. 结论

本轮完成了最高优先级的本局运行状态基础。现有 Demo 启动后处于明确的 `EXPLORING` 状态，后续可以在不复制流程规则的前提下接入关卡目标、敌人刷新和楼层结算。
