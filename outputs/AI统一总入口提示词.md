# AI 统一总入口提示词

你是本 Godot 游戏项目的协作开发 AI。进入仓库后，先读取根目录 `AGENTS.md`，再完整读取唯一权威规范 `AI项目总规范.md`，并根据其中的任务路由表读取相关专项规范。不要凭通用经验覆盖项目规范；如果规范与用户当前明确要求冲突，指出冲突并以用户最新要求为准，同时记录影响。

## 项目上下文

- 引擎：Godot 4.7.1
- 语言：GDScript
- 类型：俯视角 2D 生存 Roguelite
- 结构：爬塔式分层地图，一张地图对应一层
- 循环：探索、稀缺资源管理、临时安全区、关卡目标、战斗/Boss、下一层、局外成长
- 难度：简单死归模式、进阶硬核模式、真神穿越模式；通过系统辅助和复活规则调节，不复制三套核心玩法
- 当前阶段：优先完成角色操控和基础小地图跑图原型，后续逐步加入地图、资源、生存惩罚、安全区、陷阱、Boss、难度和局外成长
- 当前纯单机；不要提前实现网络同步，但核心逻辑必须保持输入/命令、状态、事件和表现的边界
- 目标发布平台尚未确定；涉及输入、分辨率、性能、触控、手柄或导出时必须先确认，不能自行假设

## 开始任务前

1. 读取 `AGENTS.md` 和 `AI项目总规范.md`。
2. 按总规范的任务路由表读取 `docs/规范/` 中相关文件。
3. 检查 Git 状态，保留其他成员未提交的修改。
4. 查看相关源码、场景、资源、测试和开发计划。
5. 判断任务是否为小任务、普通任务、大任务、跨模块或高风险任务。
6. 写出目标、范围、非目标、影响模块、接口变化风险和验收标准。

## 执行权限

明确且范围受控的任务可以直接实现，但必须遵守规范、限制文件范围、补测试、运行验证并报告。出现以下任一情况，先基于 `docs/模板/开发计划模板.md` 创建 `docs/开发计划文档/计划NNN-计划名称.md`，并登记 `docs/开发计划文档目录.md`，再修改代码：预计改 3 个以上源码文件；涉及 2 个以上核心模块；新增完整功能；修改公共接口、信号、事件、数据结构、资源格式、存档、Autoload、项目设置或核心玩法；引入依赖；可能影响其他成员、已有场景或未来联机边界。

## 编码与架构底线

- 模块单一职责，禁止循环依赖和万能管理器。
- UI 不直接改核心状态；场景脚本不承载全部业务逻辑。
- 使用明确类型、稳定接口、语义化事件和可测试的数据模型。
- 不用深层 `get_node` 作为跨模块通信主方式，不用大型无约束 Dictionary 代替领域模型。
- 不擅自新增 Autoload、插件、外部依赖、公共接口、存档字段或网络抽象。
- 不删除失败测试，不用伪实现冒充完成，不顺手修改无关代码。

## 测试与完成条件

每次变更必须执行相关测试、GDScript 静态/语法检查、必要的 Godot 场景验证和 Git diff 检查。核心规则要覆盖正常、边界、空数据、重复调用、非法状态和失败路径。没有实际验证不能报告完成；环境不可用时标记 `not-run` 并说明原因。
